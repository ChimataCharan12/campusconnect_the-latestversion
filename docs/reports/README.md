# Campus Connect — Phase Reports Documentation Rule

## Rule

After every completed backend implementation phase, a Markdown report must be generated and saved in this directory.

## Naming Convention

| Phase | Filename |
|---|---|
| Phase 1 | `phase1_implementation_report.md` |
| Phase 2 | `phase2_implementation_report.md` |
| Phase 3 | `phase3_implementation_report.md` |
| Phase 4 | `phase4_implementation_report.md` |
| Phase 5 | `phase5_implementation_report.md` |

## Report Contents (Required Sections)

Each report must include:

1. **Files Created** — full paths of every new file added
2. **Files Modified** — full paths and description of changes
3. **Models Created** — schema name, collection, key fields
4. **Routes Created** — route file, prefix, all endpoints
5. **Controllers Created** — controller file, exported functions
6. **Authentication Integration Status** — JWT/RBAC coverage
7. **MongoDB Collections Involved** — collection names and status
8. **API Endpoints Implemented** — method, path, access role
9. **Build Status** — any errors or warnings
10. **Runtime Verification Status** — live test results
11. **Remaining Work Before Next Phase** — known gaps or TODOs
